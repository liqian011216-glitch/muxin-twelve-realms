# 《牧心十二境》最终制作实施路线图

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已确认的最终设计拆成五个可独立运行、测试和验收的实施阶段，最终发布公开网址与二维码。

**Architecture:** React/vinext 负责旅程编排、分层叙事、签图与管理后台；一个统一的 Godot Web 包负责拓印及三个数据小游戏；Cloudflare D1 保存匿名旅程和统计。各阶段通过固定 TypeScript 类型和 `postMessage` 协议连接。

**Tech Stack:** React 19、TypeScript 5.9、vinext/Vite、Godot 4.7、GDScript、Drizzle ORM、Cloudflare D1、OpenAI Sites、Node.js test runner。

## Global Constraints

- 项目名称必须统一为《牧心十二境》。
- 第 10、11、12 境必须命名为“双泯”“入世”“牧心”。
- 手机优先并提示横屏，同时兼容电脑。
- 首次旅程严格顺序推进，互动结束后自动进入下一境，不显示前进按钮。
- 问心选牛、寻牛碰牛次数、独木桥总用时、莲花数量是牧心签唯一输入。
- 小游戏不存在失败或吉凶评价。
- 12 种核心签型，每种 5 条签文；同一旅程结果固定。
- 网站公开且玩家无需登录；不主动采集直接身份、精确位置或设备指纹。
- 普通 4G 首次完整加载目标约 30 秒内，加载后旅程中不再等待资源。
- 验收覆盖微信内置浏览器、iPhone Safari、Android Chrome 和电脑 Chrome。
- 工作区包含两个 Git 仓库：`web/` 内的站点代码在嵌套 Web 仓库提交；Godot、测试与 `docs/` 在工作区根仓库提交。不得把 `web/` 作为嵌入仓库整体加入根仓库。

## 执行与验收协议

1. 实施前先完成现有成果盘点，将每项标记为“直接保留、保留后小改、补齐、重做”。没有盘点证据不得从零重建。
2. 现有画面、代码、游戏或素材只有在验证无法满足已确认规格后才允许替换；替换前必须说明保留了什么、问题是什么、为什么局部修改不足。
3. 每个会影响画面、玩法、文案或用户体验的 Step 都是用户验收门槛。交付内容必须包含：复用内容、本次变化、查看或试玩入口、自动化验证结果、需要确认的问题。
4. 用户明确确认当前 Step 后才进入下一个可见成果 Step。内部红绿测试、格式整理和版本提交正常执行并汇报结果，但不单独制造视觉审批。
5. 十二境美术逐境制作和确认。每一境按“背景层 → 固定角色层 → 气氛层 → 合成静帧 → 动画预览”交付；该境确认后才开始下一境。
6. 已确认成果保留独立版本，不使用后续未批准尝试覆盖已批准文件。
