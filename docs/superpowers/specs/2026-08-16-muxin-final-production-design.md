# 《牧心十二境》最终制作设计规格

日期：2026-08-16  
状态：已完成口头确认，等待书面规格复核

## 1. 项目目标

将现有 Web 画面、Godot 小游戏与十二境素材整合为一条完整的浏览器体验。最终交付一个完全公开的网址和对应二维码。玩家无需注册或安装应用，在手机或电脑浏览器中打开即可完成 15～20 分钟的《牧心十二境》旅程，并获得一张可保存的“牧心签”。

项目统一名称为《牧心十二境》。第 10、11、12 境分别为“双泯”“入世”“牧心”。

## 2. 目标设备与访问方式

- 手机优先，同时兼容电脑。
- 手机端以横屏体验为标准；竖屏打开时先提示旋转设备。
- 网站完全公开，任何获得链接或二维码的人都可直接体验。
- 不要求玩家注册、登录或填写昵称。
- 首次完整加载完成后，十二境与小游戏之间不再出现资源等待。
- 普通 4G 网络下首次完整加载的目标为约 30 秒以内，并显示水墨风加载进度。

## 3. 完整体验流程

### 3.1 开场

1. 水墨风加载页一次性预加载完整体验。
2. 《牧心十二境》首页。
3. 大足石刻与牧牛图背景介绍。
4. 问心选牛：未牧之牛、受制之牛、自在之牛。
5. 选牛后不解释心理含义，只记录选择，留待最终牧心签揭示。
   - 完整保留已确认的三牛静态画面、名称和排列。
   - 点击一头牛后立即记录并锁定本次选择，不接受连续点击改选。
   - 选中项只显示朱红描边，另外两项降低亮度；不显示“已择”或其他文字印记。反馈停留 0.8 秒后自动进入石刻文化介绍序列。
   - 首次旅程中不能返回修改选牛结果；只有重新开始旅程才能重新选择。
6. 完整保留现有多页石刻文化介绍；这些页面位于问心选牛之后、开场拓印之前，不属于正式十二境。
7. 玩家在最后一张介绍页点击进入拓印。拓印小游戏作为入境仪式，不参与牧心签计算。

### 3.2 十二境顺序

首次旅程必须依序进行：

1. 未牧：牛挣脱，以叙事互动表现心之初乱。
2. 初调：进入 60 秒寻牛小游戏。
3. 受制：表现人与牛、绳索与控制之间的冲突。
4. 回首：人与牛第一次真正相互注视。
5. 驯伏：进入独木桥小游戏。
6. 无碍：牛主动跟随牧人，人牛不再对抗。
7. 任运：玩家只需顺其自然地前行。
8. 相忘：进入莲花跳跃小游戏。
9. 独照：暂停并观照自身。
10. 双泯：人与牛的分别逐渐消失。
11. 入世：青年牧人与水牛进入大足石刻现实空间，连接千手观音、牧牛图与现实人间。
12. 牧心：牧人与牛逐渐化入山水，留下月、莲台、石碑和墨痕，随后生成牧心签。

### 3.3 境界衔接

- 每境开始时淡入少量竖排境名、寓意或引导文字，阅读后自动淡出。
- 完成当前互动后，不显示“下一步”或“循迹前行”按钮。
- 反馈文字或动画自然结束并短暂停留后，画面自动淡出进入下一境。
- 三个小游戏完成后自动回到主流程。
- 除静音和退出旅程等必要控制外，不加入破坏沉浸感的常驻操作。

### 3.4 进度与回看

- 旅程进度自动保存在当前浏览器。
- 中途关闭后再次打开，显示“继续旅程”和“重新开始”。
- 首次完整通关后开放十二境自由回看。
- 重新开始会创建新的匿名旅程，并允许生成新的牧心签。

## 4. 视觉系统

### 4.1 风格基准

十二境以 `审查版_H5制作包/12境审查总览.png` 为整体视觉基准：

- 淡米色绢纸底；
- 工笔线描结合浅水墨；
- 石青、黛蓝为主要冷色；
- 少量赭石、朱红花草作为点缀；
- 大面积留白与横向山水构图；
- 人物和牛保持较小尺度，景大于人；
- 避免高饱和色、现代卡通感和厚重游戏界面。

### 4.2 固定角色

- 十二境始终使用同一位青年牧人和同一头水牛。
- 牧人严格遵循已提供的三视角色图：固定脸型、斗笠、蓝灰短衣、黑裤、赤足、竹杖与绳索。
- 水牛严格遵循已提供的三视角色图：固定牛角、体型、毛色与纹理。
- 牧人不随境界变老，只通过动作、神态、位置和与牛之间的距离表现心境变化。
- 角色的基本外貌不得因场景重新生成而漂移。

### 4.3 动画方式

十二境采用分层画面动画。背景、山石、花草、云雾、牧人、水牛和绳索拆为可独立运动的透明图层，使用克制的局部运动：

- 云雾漂移；
- 水纹扩散；
- 草木与衣摆轻摆；
- 人与牛的呼吸、回望和小幅动作；
- 绳索松紧变化；
- 缓慢镜头推进、横移与淡化。

不采用每境完整视频，也不只对整张平面图做简单缩放。

### 4.4 声音

- 加入统一背景音乐、自然环境音和操作音效。
- 全程提供清晰但克制的静音按钮。
- 浏览器首次需要用户操作才能播放声音时，以首次点击“开始旅程”完成音频解锁。

## 5. 小游戏设计

开场拓印及三个数据小游戏均保留现有视觉风格，不重新绘制。寻牛与独木桥保留已有核心手感并按手机端修正；莲花跳跃只保留美术素材和叙事方向，玩法运行层按手机横屏重建。技术上合并为一个优化后的 Godot Web 游戏包，共用角色、字体、声音与公共素材，按旅程位置打开对应游戏场景。拓印只返回完成状态，不参与牧心签；寻牛、独木桥与莲花跳跃返回用于签文计算的核心数据。

### 5.1 寻牛

- 固定体验 60 秒。
- 手机端点击或按住画面中的方向，人物向该方向移动，不显示虚拟摇杆。
- 不存在失败状态。
- 核心记录：60 秒内人物碰到牛的次数。
- 辅助统计：移动距离、停留时长等，不参与牧心签。
- 60 秒结束后自然回到主流程。

### 5.2 独木桥

- 点击屏幕左半边向左修正，点击右半边向右修正，不显示额外左右按钮。
- 玩家必须最终到达对岸。
- 失衡掉落后人物从桥头重新开始，但总计时不重置。
- 不显示“失败”或“游戏结束”。
- 核心记录：从第一次开始到最终到达对岸的总用时。
- 掉落次数只用于后台统计，不参与牧心签。
- 连续体验达到 3 分钟时，出现“让风扶你一程”，可开启更容易的平衡模式；辅助模式仍要求玩家走到对岸。

### 5.3 莲花跳跃

- 现有电脑式玩法代码不作为最终基础；保留背景、人物动画与莲花素材，重建手机玩法层。
- 人物以稳定速度自动向前移动；手机横屏全画面点击跳跃，空中允许再点击一次二段跳，不显示左右或跳跃按钮。
- 正常通关时长为 45～60 秒，玩家可以漏收莲花，到达终点即完成。
- 掉落后从最近的安全节点继续，已收集莲花和总计时不重置，不判定失败。
- 核心记录：收集到的莲花数量。
- 总用时和掉落次数只用于后台统计，不参与牧心签。
- 完整重建和分步验收规则见 `docs/superpowers/specs/2026-08-16-lotus-mobile-rebuild-design.md`。

### 5.4 游戏与网页通信

网页向 Godot 发送要打开的拓印或小游戏场景、旅程编号与本次互动编号。Godot 完成互动后向网页返回结构化结果。网页校验互动类型与数据范围后保存结果并推进旅程。重复回传必须具有幂等性，不能重复累计同一局数据。

## 6. 牧心签系统

### 6.1 输入数据

牧心签只由四项核心数据决定：

1. 问心所选的牛；
2. 寻牛碰到牛的次数；
3. 独木桥最终过桥总用时；
4. 莲花跳跃收集的莲花数量。

其他境界中的点击、停留与选择只用于叙事推进和匿名体验统计，不参与签文计算。

### 6.2 计算方式

- 使用可配置的加权规则矩阵将四项输入转换为心行倾向。
- 综合倾向映射到 12 种核心签型。
- 每种核心签型准备 5 条不同签文，共至少 60 条。
- 签型不区分吉凶、上签或下签，每一种都代表不同的观心状态。
- 旅程完成时使用匿名旅程编号生成固定结果种子，从对应签型的 5 条签文中稳定选择一条。
- 同一次旅程刷新或重新打开结果页时，签型和签文保持不变。
- 只有重新开始新的旅程，结果才重新计算。

### 6.3 最终签图

最终页面展示签名、签文和对本次旅程的含蓄解释。系统将结果渲染为适合手机保存与微信转发的纵向签图，并提供：

- 保存图片；
- 再走一程。

不生成公开的个人结果链接。

## 7. 匿名数据与管理后台

### 7.1 数据原则

- 每次新旅程生成随机匿名旅程编号。
- 不要求玩家登录。
- 不主动采集姓名、手机号、微信号、精确位置或设备指纹。
- 玩家端不显示匿名统计提示。
- 数据长期保存，管理员可手动清空。

### 7.2 保存内容

- 匿名旅程编号；
- 创建、继续与完成时间；
- 当前境界和完成进度；
- 问心选牛结果；
- 三个小游戏的核心与辅助统计；
- 最终签型与签文版本；
- 手机或电脑、横竖屏状态、浏览器类型；
- 是否使用独木桥辅助模式。

### 7.3 管理页面

- 独立管理路径，使用安全的管理员密码登录。
- 密码作为托管环境中的秘密配置，不写入前端代码。
- 显示体验人数、完成率、平均体验时长、问心选牛比例、小游戏数据分布和 12 种签型分布。
- 可以查看单次匿名旅程详情。
- 支持导出 CSV。
- 清空数据属于高风险操作，必须再次确认。

### 7.4 数据存储

使用当前 Sites 托管平台自带的数据库。应用使用服务端接口写入和读取统计，玩家端不能直接查询全量数据或绕过管理员权限。

## 8. 系统结构

### 8.1 Web 旅程层

负责首页、背景介绍、问心、拓印、十二境叙事、进度恢复、音频、自动转场、最终签图和管理页面。

### 8.2 Godot 游戏层

负责开场拓印、寻牛、独木桥和莲花跳跃。四个场景共享一个 Web 导出包，并通过明确的消息协议与 Web 旅程层通信；只有后三个场景的核心结果进入牧心签计算。

### 8.3 数据与签文层

负责匿名旅程、游戏结果校验、进度保存、签型计算、固定签文抽取、后台聚合统计与 CSV 导出。

各层之间使用固定数据结构通信，避免页面组件直接修改数据库或 Godot 内部状态。

## 9. 性能策略

- 去除当前多个 Godot 导出包中重复的公共资源。
- 合并小游戏并只保留实际使用的场景和素材。
- 对图片、纹理、音频和字体进行 Web 适配压缩。
- 加载页显示真实进度，禁止伪进度长时间停滞。
- 完整资源加载并校验成功后才进入首页。
- 加载失败时提供“重新加载”，保留已经成功缓存的资源。
- 使用浏览器缓存减少再次进入时的等待。

## 10. 异常与恢复

- 旅程状态在每次关键选择、游戏结束和境界切换时保存。
- 页面刷新、浏览器关闭或网络短暂中断后，可以恢复到最近完成的安全节点。
- 如果小游戏结果通信超时，保留游戏界面并允许重新连接，不得静默伪造结果。
- 后台写入失败时先保存在本机重试队列，不阻断玩家继续体验或生成牧心签。
- 签图保存不受后台统计写入失败影响。
- 音频不可用时体验仍可完整继续。

## 11. 测试与验收

### 11.1 功能验收

- 三种问心选择均可完成全流程。
- 三个小游戏在不同数据结果下均能返回主流程。
- 十二境按顺序自动衔接，无额外前进按钮。
- 中途退出后可继续或重新开始。
- 首次通关后可自由回看十二境。
- 相同旅程始终获得相同签，不同输入能覆盖 12 种签型。
- 签图可以在手机保存。
- 匿名数据、统计图表、单次详情与 CSV 数据一致。

### 11.2 浏览器验收

- 微信内置浏览器；
- iPhone Safari；
- Android Chrome；
- 电脑 Chrome。

检查横屏提示、触摸控制、音频解锁、画面比例、加载恢复和图片保存。

### 11.3 性能验收

- 普通 4G 环境下首次完整加载目标约 30 秒以内。
- 加载完成后的十二境和小游戏切换不再出现资源等待。
- 再次访问能够有效利用浏览器缓存。

### 11.4 发布流程

1. 完成本地构建与自动化测试。
2. 发布测试版本供项目方完整验收。
3. 根据验收意见修正并重新验证。
4. 项目方确认后切换为完全公开访问。
5. 交付平台正式网址和对应二维码图片。

## 12. 明确不在当前范围内的内容

- 玩家账号、昵称和社交关系；
- 排行榜、分数胜负或失败结算；
- 精确地理位置和设备指纹；
- 公开的个人结果链接；
- 独立原生 iOS 或 Android 应用；
- 发布前购买或绑定独立域名。
