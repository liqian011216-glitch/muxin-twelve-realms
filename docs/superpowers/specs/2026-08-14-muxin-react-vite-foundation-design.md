# 《牧心十二境》React + Vite 网页基础架构设计

## 目标

在不删除或重构现有 Godot 工程与 `web/` 项目的前提下，于仓库根目录新增独立的 `frontend/` React + Vite 单页应用。第一阶段只建立完整网页架构、基础内容、统一视觉与数据结构，不开发或加载 Godot 游戏。

## 项目边界

- 新前端位于 `frontend/`，拥有独立的 `package.json`、Vite 配置、测试配置和 `src/`。
- 现有 `web/`、Godot 场景、脚本、游戏素材与构建产物保持原样。
- 第一阶段不复制大型现有素材；页面使用 CSS 形成宣纸、淡墨、描金与留白氛围。
- 为后续 Godot Web 导出约定 `frontend/public/games/<game-name>/`，但本阶段不创建游戏构建产物。

## 路由与叙事顺序

React Router 管理以下路由，并按固定顺序形成基础叙事：

1. `/`：首页 Home
2. `/question`：问心页面 Question
3. `/stone`：石刻介绍 StoneIntro
4. `/rubbing`：拓印入口 Rubbing
5. `/realm`：十二境 Realm
6. `/games`：小游戏入口 Games
7. `/sign`：最终牧心签 Sign

每个页面显示标题、简短说明、返回按钮与下一步按钮。首页返回按钮禁用；牧心签页的下一步按钮改为“重新游历”并返回首页。未知地址回到首页，避免出现无内容页面。

## 组件边界

- `App.jsx`：声明路由，不承载具体页面内容。
- `Navigation.jsx`：显示全局品牌与章节入口，当前路由具有明确状态。
- `Button.jsx`：统一主按钮、次按钮和禁用状态，并兼容 React Router 链接。
- `PageTransition.jsx`：提供公共页面容器与轻量淡入效果，尊重减少动态效果的系统设置。
- 页面组件：只组合内容、数据与前后导航，不重复实现公共视觉。

## 数据结构

### `stoneData.js`

保存石刻名称、年代、位置、图片路径、专业介绍和趣味介绍。图片字段先使用可替换的资源路径或空值，后续补入获得授权的石刻图像时不需要改变页面接口。

### `realmData.js`

保存十二境的编号、名称及基础说明：未牧、初调、受制、回首、驯伏、无碍、任运、相忘、独照、双泯、入世、牧心。数据与页面渲染分离，后续可扩展图片、互动类型、Godot 场景地址与行为权重。

### `signData.js`

保存牧心签的维度、签文基础模板和未来行为映射说明。第一阶段只提供稳定的数据接口，不实现用户画像或随机生成算法。

## 视觉方向

- 背景：宣纸暖白与轻微纤维纹理，不使用纯白科技背景。
- 主色：墨黑、淡墨灰、朱砂棕、低饱和金色。
- 字体：优先中文宋体与系统衬线字体，形成克制、文献化的阅读感。
- 构图：大面积留白、细描金分隔线、竖向题签和低对比水墨晕染。
- 控件：克制的文字按钮和细框，不使用卡通插画、积分、徽章或游戏大厅式卡片。
- 响应式：桌面端保持展陈感，窄屏下导航可换行，按钮保持可触达。

## Godot Web 接入约定

`Games` 页面保留语义明确的游戏承载区域。后续将 Godot HTML5 导出到 `frontend/public/games/<game-name>/` 后，可通过独立组件封装 `iframe` 或 Godot Web 启动器。网页与游戏之间预留 `postMessage` 事件边界，未来可传递开始、完成、退出和行为结果；第一阶段不实现通信。

## 测试与验收

- 路由测试：七个路径均渲染正确页面标题。
- 导航测试：页面的返回与下一步目标符合叙事顺序。
- 数据测试：十二境数量为 12，编号连续，名称与需求一致；石刻和签数据包含约定字段。
- 质量检查：测试、ESLint 与 Vite 生产构建均成功。
- 人工检查：页面具有宣纸、淡墨、描金和留白的统一感，且没有游戏化或卡通化组件。
- 范围检查：现有 `web/` 和 Godot 文件无新增修改。

## 运行方式

进入 `frontend/` 后安装依赖并启动：

```bash
npm install
npm run dev
```

生产构建使用：

```bash
npm run build
```
