# 莲花收集手机端玩法重建设计

日期：2026-08-16
状态：用户已确认设计内容，等待书面规格复核

## 1. 目标

将现有面向电脑网页的横向莲花收集游戏改造成手机横屏优先的单指游戏。保留已经确定的水墨视觉、人物动画和莲花素材，重建玩法控制与关卡运行层。正常一次通关控制在 45～60 秒；游戏不存在失败，玩家抵达彼岸即完成，最终记录实际收集的莲花数量。

## 2. 保留与重建边界

### 保留

- 现有水墨背景、人物造型、人物动画和莲花素材；
- 已确定的整体色彩、画面风格与第八境“相忘”的叙事位置；
- Godot 统一 Web 游戏包及网页与游戏之间的统一消息协议方向。

### 重建

- 人物自动奔跑控制器；
- 单指点击、二段跳和输入缓冲；
- 平台碰撞与安全落点判定；
- 隐藏检查点与掉落恢复；
- 横向镜头跟随；
- 莲花的一次性收集状态；
- 游戏内提示、完成状态和结果回传；
- 手机横屏适配与真实设备验收。

### 删除

- 左右移动输入与屏幕方向按钮；
- 独立跳跃按钮和电脑键盘式操作说明；
- 失败结算、游戏结束和重新挑战流程；
- 掉落后整局重新开始或清空已收集莲花的逻辑。

## 3. 操作与关卡流程

1. 游戏进入后使用一句简短提示说明“点击跳跃，再次点击二段跳”。
2. 人物以稳定速度自动向右奔跑，玩家不能手动左右移动。
3. 游戏画面的非功能按钮区域均可触发跳跃；鼠标点击和空格键只作为电脑兼容输入。
4. 地面点击触发第一次跳跃，腾空后再次点击触发一次二段跳，落地后重置跳跃次数。
5. 使用跳跃输入缓冲和短暂的离地宽限，避免手机点击时序造成无响应；一次点击只能消费一次跳跃。
6. 完整关卡的正常通关时长为 45～60 秒。
7. 莲花同时分布在普通路线和风险稍高的路线。玩家可以漏收，漏收不影响通关，也不能向左折返刷取。
8. 到达彼岸立即锁定结果并结束，不显示重玩结算，随后自动回到十二境主流程。

## 4. 检查点与无失败规则

- 在完整关卡的稳定平台处设置 4～5 个隐藏安全节点。
- 人物通过安全节点后才更新最近检查点，不能用单纯的横坐标百分比推算不安全落点。
- 掉落或进入异常区域时，画面短暂淡出并从最近检查点继续。
- 已收集莲花保持收集状态，同一朵莲花在本局内最多计数一次。
- 总用时和掉落次数继续累计。
- 全程不得显示“失败”“游戏结束”“重新挑战”等信息。
- 如果人物卡入地形或跌出地图边界，同样走检查点恢复流程。

## 5. 数据规则

完成时产生以下结果：

```json
{
  "lotuses": 0,
  "elapsedSeconds": 0,
  "falls": 0
}
```

- `lotuses` 是参与牧心签计算的唯一核心数据；
- `elapsedSeconds` 和 `falls` 只用于匿名辅助统计，不影响签文；
- 页面切到后台、锁屏或标签页不可见时暂停游戏和计时，恢复可见后继续；
- 页面意外刷新时只重新开始本次莲花关卡，不清除此前旅程进度；
- 到达彼岸后结果只允许提交一次，重复事件不得重复记数或推进两次旅程。

## 6. 手机与性能要求

- 最终设计标准是手机浏览器横屏，竖屏状态由网页旅程层提示旋转设备；
- 安全区域适配带刘海、挖孔和底部手势条的设备；
- 弱性能设备优先维持输入、碰撞和镜头稳定，可降级粒子、水纹和远景动态；
- 不降低人物、平台边缘和莲花的辨识度；
- 电脑浏览器保留鼠标点击与空格键兼容，但不以电脑操作作为验收标准。

## 7. Bug 处理与验收门槛

### 实施前

先运行并记录现有版本的可复现 Bug，至少覆盖：电脑式左右控制、触摸按钮、失败结算、掉落重置、碰撞异常、镜头异常、重复收集和重复提交。旧测试中维护错误规则的断言必须先改为新规格，并验证它们在旧实现上失败。

### 可见验收 Step A：手感样段

先只制作 10～15 秒手机试玩段，展示：

- 自动奔跑速度；
- 首跳高度与距离；
- 二段跳时机；
- 点击响应；
- 掉落后最近节点恢复。

用户确认手感后才扩展完整关卡。

### 可见验收 Step B：完整关卡

扩展为 45～60 秒关卡，展示平台节奏、4～5 个安全节点、普通与风险莲花路线。用户确认关卡难度后才接入最终结果。

### 可见验收 Step C：结果与主流程

验证莲花一次性计数、掉落保留、后台暂停、到岸单次提交和自动返回十二境。最后使用真实手机横屏验收，并补测电脑浏览器。

## 8. 完成标准

- 手机横屏下不出现左右或跳跃按钮；
- 自动奔跑、点击跳跃和二段跳稳定可用；
- 正常通关耗时处于 45～60 秒；
- 玩家可以漏收莲花并正常到达彼岸；
- 掉落后从安全节点继续，莲花和计时不重置；
- 游戏内没有失败状态；
- 莲花数准确且只提交一次；
- 用户依次确认手感样段、完整关卡和结果衔接。
