# 牧心十二境：十二境叙事与随机签系统设计

## 目标

把现有 Figma 画面、12 境插画和四个小游戏串成一条可完成的 H5 体验。除小游戏节点外，每一境提供一段短剧情和一个简单交互；玩家的选择与游戏操作被记录为心迹，最后随机生成大量不同的签。

## 体验流程

```text
Figma 封面 → Figma 序言 → Figma 初始选择 → Figma 入境过渡
                                              ↓
                                           开场拓印
                                              ↓
                                             未牧
                                              ↓
                                           寻牛游戏
                                              ↓
                               初调 → 受制 → 回首 → 驯伏
                                                        ↓
                                                   独木桥游戏
                                                        ↓
                                                     无碍 → 任运 → 相忘
                                                                  ↓
                                                           横向跳跃游戏
                                                                  ↓
                                               独照 → 双忘 → 禅定 → 心月图
                                                                  ↓
                                                                 抽签
```

网页是主叙事层，Godot 是四个互动节点。小游戏不显示传统分数，不负责最终签的判定，只输出行为标签和简短结果。

### Figma 前置页面

现有 Figma 页面必须位于开场拓印之前，作为用户进入十二境前的引导层：

1. `00-cover`：封面，点击“问心”开始；
2. `01-intro`：说明牧心之旅和观看方式；
3. `02-choice`：完成第一次选择，记录初始心迹；
4. `03-stone-intro` 至 `15-summary`：连续展示现有多页石刻文化介绍；
5. 最后一张介绍页由玩家点击进入开场拓印；
6. 用户完成拓印互动后进入第一境“未牧”。

这些介绍页不替代 12 境，也不直接生成签；它们只负责建立语境并写入第一次选择。开场拓印完成后才进入 12 境主流程。

## 十二境交互设计

每一境使用统一结构：插画背景、境名、两到三句短文、一个主交互、选择后的一句反馈、继续按钮。选择不切换到独立页面，只更新当前境的文案和心迹。

| 境 | 剧情交互 | 记录标签 | 后续 |
|---|---|---|---|
| 1 未牧 | 点击牛挣脱的方向，选择追上、停下或呼唤 | `chase` / `wait` / `look_back` | 寻牛游戏 |
| 2 初调 | 寻牛后的回应：继续靠近、观察牛、放松脚步 | `chase` / `wait` / `let_go` | 进入受制 |
| 3 受制 | 选择拉紧缰绳、松一点、解开 | `control` / `wait` / `let_go` | 进入回首 |
| 4 回首 | 风雨来时选择追上、回望来路、呼唤牛 | `chase` / `look_back` / `wait` | 进入驯伏 |
| 5 驯伏 | 独木桥前选择并肩、让牛先走、自己先走 | `同行` / `wait` / `control` | 独木桥游戏 |
| 6 无碍 | 过桥后选择继续握绳、把绳挂起、完全放开 | `control` / `wait` / `let_go` | 进入任运 |
| 7 任运 | 选择顺风的小路、旧蹄印、没有路的方向 | `let_go` / `look_back` / `chase` | 进入相忘 |
| 8 相忘 | 听笛时选择寻找牛、听笛、看水中倒影 | `chase` / `wait` / `look_back` | 横向跳跃游戏 |
| 9 独照 | 泉边选择靠近、停留观看、转身离开 | `chase` / `wait` / `let_go` | 进入双忘 |
| 10 双忘 | 点击猿猴、牛或空白，之后自动转场 | `control` / `look_back` / `let_go` | 自动进入禅定 |
| 11 禅定 | 静止停留片刻，点击月光或不点击 | `wait` / `let_go` | 进入心月图 |
| 12 心月图 | 选择留下牛、留下脚下的路、留下空白 | `look_back` / `chase` / `let_go` | 生成最终签 |

其中 1、5、8 是小游戏前置，游戏完成后回到网页继续剧情；拓印作为开场和结尾的网页互动，不计入四个小游戏。Figma 前置页面位于开场拓印之前。

## 游戏输出协议

小游戏不需要分数。每个游戏结束时返回一个轻量事件对象：

```ts
type GameResult = {
  game: "stone_rubbing" | "seek_cow" | "bridge" | "jump";
  actions: string[];
  result: "chase" | "wait" | "look_back" | "let_go" | "control" | "同行";
};
```

网页将 `actions` 转换为统一标签，并累加到玩家心迹。现阶段如果真实 Godot Web 回传尚未接通，网页提供同样协议的模拟适配器，先保证完整叙事可以跑通；接通 Godot 后只替换适配器，不改章节和签库逻辑。

## 心迹与签型

统一状态结构：

```ts
type JourneyState = {
  counts: Record<"chase" | "wait" | "look_back" | "let_go" | "control" | "同行", number>;
  choices: string[];
  gameResults: GameResult[];
  finalSeal: "cow" | "path" | "blank";
};
```

签型由最高的两类行为组成，平分时使用最近一次行为和最终拓印选择打破平分。例如：

- `追逐 × 回望`
- `等待 × 放手`
- `回望 × 留白`
- `追逐 × 控制`
- `等待 × 同行`
- `放手 × 无碍`

为了增加实际结果数量，每个签型包含多个签文版本。第一版准备 20 个左右签型，每个签型 3–6 个随机版本，约 60–120 种可抽取签。签文随机只在匹配签型内发生，不会完全脱离玩家行为。

## 签的展示内容

最终签页包含：

1. 签号与签名；
2. 上签/中签/下签或“无碍、未定”等非分数型状态；
3. 两到四句签文；
4. 一段结合玩家路径的解签；
5. 记录的心迹标签；
6. 重新入境按钮。

签的随机种子使用本次旅程的选择记录和时间戳生成，使同一路径重复游玩时仍可能抽到不同版本；刷新当前页面不会在同一次结算中重复抽取。

## 交互与错误处理

- 任意章节选择后都必须有明确视觉反馈，并允许继续；
- 小游戏退出或未返回结果时，使用默认的 `wait` 标签继续，不阻塞主叙事；
- 结尾没有分数排行榜，不显示“失败”；
- 移动端保持单屏可操作，章节文本不遮挡核心画面；
- 所有热点按钮提供无障碍标签和键盘焦点样式。

## 验收标准

- 用户可以从开场走到心月图，不会卡在章节或小游戏节点；
- 12 境全部有画面、剧情、至少一个选择/交互和反馈；
- 四个小游戏节点均能产生行为标签，即使先使用模拟结果也能完成流程；
- 同一次旅程只生成一支签；重新游玩同一路径可以抽到同签型的不同签文；
- 至少有 60 种实际签文结果，签型与玩家行为一致；
- `web` 项目构建通过。
